# Stackwell — руководство разработчика

*Stackwell — Developer Guide*

## 1. Архитектура

Stackwell разделён на несколько небольших частей:

- **Core** — жизненный цикл приложения, конфигурация и журналирование.
- **Plugin runtime** — поиск нативных библиотек, проверка дескриптора ABI и вызов initialize/shutdown.
- **CLI** — команды для получения сведений о хосте и списка плагинов.
- **Desktop** — Windows GUI на Win32, Direct2D и DirectWrite.

Хост не содержит необязательные продуктовые модули. Один плагин распространяется как один нативный файл. Исходники SDK и примеры находятся в отдельном репозитории [Stackwell Plugins](https://github.com/Null-Workspace/Stackwell-plugins).

Важные каталоги:
- `app/` — точки входа CLI и Desktop;
- `include/stackwell/` — публичные заголовки хоста;
- `src/core/` — ядро;
- `src/plugin/` — загрузчик плагинов;
- `src/commands/` — команды CLI;
- `src/ui/suf/` — Windows desktop shell;
- `resources/config/` — конфигурация по умолчанию;
- `cmake/` — настройки компилятора.

## 2. Требования и сборка хоста

Текущий основной сценарий разработки — Windows x64.

Необходимы:
- Windows 10/11 x64;
- Visual Studio 2026 с workload **Desktop development with C++**;
- CMake 3.25+;
- vcpkg и переменная окружения `VCPKG_ROOT`;
- Git.

Зависимости из vcpkg manifest:
- CLI11;
- spdlog;
- nlohmann-json.

Из корня репозитория выполните:

```powershell
cmake --preset "Visual Studio Community 2026 Release - amd64"
cmake --build --preset "Visual Studio Community 2026 Release - amd64-debug"
```

Несмотря на слово Release в имени configure preset, приведённый build preset собирает конфигурацию **Debug**. Для конфигурации Release можно выполнить:

```powershell
cmake --build "out/build/Visual Studio Community 2026 Release - amd64" --config Release
```

Результат находится в:

```text
out/build/Visual Studio Community 2026 Release - amd64/
  dist/
    bin/
      stackwell.exe
      stackwell-desktop.exe
    resources/
      config/
        config.json
    plugins/
```

Каталог plugins создаётся приложением при первом запуске. CLI собирается на всех поддерживаемых CMake-платформах; desktop target создаётся только на Windows.

## 3. Plugin API v1

Канонический заголовок ABI в этом репозитории:

`include/stackwell/plugin/plugin_api.h`

SDK, примеры и каталог публикуются в [Null-Workspace/Stackwell-plugins](https://github.com/Null-Workspace/Stackwell-plugins). При разработке плагина сверяйте SDK header с версией API хоста.

API v1 предоставляет:
- версию API и размер структуры `StackwellHostApi`;
- `log_info` и `log_error` для записи в журнал хоста;
- функцию инициализации плагина;
- функцию завершения работы;
- метаданные плагина и минимальную версию хоста.

В API v1 пока нет регистрации GUI-страниц, команд, межплагинного обмена сообщениями или событийной шины.

### Жизненный цикл

1. Хост сканирует верхний уровень настроенной папки плагинов.
2. Загружает файлы с платформенным расширением: `.dll`, `.so` или `.dylib`.
3. Ищет экспорт `stackwell_plugin_query`.
4. Проверяет размер дескриптора, API version, обязательные поля и метаданные.
5. Проверяет `min_host_version`, если оно задано.
6. Вызывает `initialize(const StackwellHostApi*)`.
7. При завершении приложения вызывает `shutdown()` для успешно инициализированных плагинов в обратном порядке.

Возврат `0` из initialize означает успех. Любое ненулевое значение считается ошибкой инициализации.

### Обязательный контракт

Плагин должен экспортировать функцию с C linkage и согласованным calling convention:

```cpp
const StackwellPluginDescriptor*
STACKWELL_PLUGIN_CALL stackwell_plugin_query(void);
```

Дескриптор обязан содержать:
- `struct_size`;
- `api_version` (для текущего хоста — `STACKWELL_PLUGIN_API_VERSION`);
- `name`;
- `version`;
- `initialize`;
- `shutdown`.

Поля `author`, `description`, `min_host_version` являются дополнительными и должны читаться хостом только при достаточном `struct_size`. Минимальная версия хоста задаётся в формате `major.minor.patch`.

### Рекомендации ABI

- Не меняйте calling convention и C ABI сигнатуры.
- Не передавайте через границу ABI объекты STL, исключения C++ или владение памятью, зависящее от CRT.
- Не выбрасывайте исключения через границу плагин/хост.
- Сохраняйте строки метаданных доступными на протяжении всего времени жизни библиотеки.
- Проверяйте указатели и входную структуру Host API.
- Делайте initialize устойчивой к повторному запуску только если это явно требуется вашим собственным кодом; хост вызывает её один раз на загрузку.
- Не используйте функции хоста, которых нет в объявленном API.

## 4. Сборка плагинов

Используйте [репозиторий Stackwell Plugins](https://github.com/Null-Workspace/Stackwell-plugins) как стартовую точку: там находятся SDK header, минимальный пример, Diagnostics plugin и CMake-конфигурация.

Плагин собирается в отдельную динамическую библиотеку. Для конечного пользователя результатом должен быть один файл:
- Windows: `.dll`;
- Linux: `.so`;
- macOS: `.dylib`.

Не распространяйте исходный каталог плагина как будто это готовый модуль. Исходники и готовая библиотека — разные артефакты.

## 5. Установка и проверка

Скопируйте готовую библиотеку непосредственно в папку `plugins` дистрибутива Stackwell и перезапустите хост.

Проверьте:
- GUI: страница Plugins и состояние Initialized;
- CLI: `stackwell.exe plugins`;
- журнал: `logs/stackwell.log`.

Не проверяйте плагин только по наличию файла: успешная загрузка и успешная инициализация — отдельные состояния.

## 6. Правила совместимости

- Совпадение архитектуры обязательно.
- Версия Plugin API должна совпадать с API хоста.
- Если указана `min_host_version`, текущая версия хоста должна быть не ниже неё.
- Имя плагина должно быть уникальным без учёта регистра.
- Имя, версия и строки метаданных имеют ограничение длины; см. константы в `src/plugin/plugin_manager.cpp`.

## 7. Безопасность и доверие

Загрузка DLL — выполнение нативного кода внутри процесса Stackwell. Плагин получает права процесса и не изолируется от хоста или ОС.

Не считайте проверку SHA-256 проверкой безопасности: она лишь подтверждает совпадение байтов с опубликованной суммой. Проверяйте источник релиза, исходный код и права, которые имеет процесс.

## 8. Ограничения текущего API

Plugin API v1 — минимальный lifecycle/logging ABI. Он не предоставляет UI extension points, команды, настройки плагинов, IPC или sandbox. Не документируйте эти возможности как доступные, пока соответствующие интерфейсы не появятся в SDK и хосте.

Перед выпуском новой версии плагина проверьте его на чистой установке хоста, пустой папке plugins и на конфигурации с несколькими DLL.
