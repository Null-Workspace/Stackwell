# Stackwell 0.1.0 — First Working Version

**Release line:** 0.1.x  
**Status:** initial host foundation  
**Target package:** Windows x64

## What is included

- C++20 application core with startup and shutdown lifecycle.
- JSON configuration and rotating application logs.
- Native plugin discovery from one configured directory.
- Plugin API v1 descriptor validation and initialize/shutdown lifecycle.
- CLI commands: `info` and `plugins`.
- Native Windows desktop shell with Overview, Plugins and Settings pages.
- Separate public repository for plugin SDK, examples and community catalog.

## Important limitations

This is the first working host foundation, not a complete system-administration product.

- No in-app plugin catalog, download, install, update or uninstall flow.
- Plugins are installed manually by placing one native library file in the plugins directory.
- The host scans plugins at startup; restart after adding or removing a module.
- Plugin API v1 exposes logging and lifecycle only. Plugins cannot add GUI pages or CLI commands through the host API.
- Settings page is informational; it does not edit configuration.
- Native plugins are not sandboxed and run with the host process permissions.
- The desktop application is Windows-only. No prebuilt Linux/macOS desktop package is provided.
- No standalone setup wizard or automatic updater is included.

## Package contents

The Windows package workflow produces a ZIP containing the distribution directory:
- `bin/stackwell-desktop.exe`;
- `bin/stackwell.exe`;
- `resources/config/config.json`.

The application creates the configured plugins, logs and data directories when it starts.

## Verification

A release is considered published only after the tagged GitHub Actions workflow completes successfully and the release ZIP is visible on the [Releases page](https://github.com/Null-Workspace/Stackwell/releases). A source commit or Git tag alone is not a binary release.

## Upgrade notes

Keep a backup of `resources/config/config.json` and the `plugins` directory before replacing an existing distribution. Check plugin API compatibility before carrying native modules across host versions.
