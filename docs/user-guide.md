# Stackwell — руководство пользователя

*Stackwell — User Guide*

## 1. Что такое Stackwell

Stackwell — это приложение-хост. Само приложение отвечает за запуск, конфигурацию, журналирование и загрузку плагинов. Дополнительные функции поставляются отдельными нативными модулями.

Если папка плагинов пуста, Stackwell всё равно запускается, но не предоставляет дополнительных системных инструментов. Это ожидаемое поведение.

## 2. Получение и запуск

1. Откройте [страницу релизов Stackwell](https://github.com/Null-Workspace/Stackwell/releases).
2. Скачайте архив Windows x64 для нужной версии, когда он опубликован.
3. Распакуйте архив целиком в отдельную папку. Не запускайте EXE прямо из ZIP.
4. Запустите `stackwell-desktop.exe` для графического интерфейса или `stackwell.exe` для командной строки.
5. При первом запуске приложение создаёт рабочие папки, указанные в конфигурации.

Не перемещайте EXE отдельно от папки `resources`: конфигурация загружается относительно структуры дистрибутива.

> В версии 0.1.x доступен Windows desktop host. Если на странице релизов ещё нет готового архива, значит пакет пока не опубликован; сборка из исходников описана в [руководстве разработчика](developer-guide.md).

## 3. Графический интерфейс

Окно Stackwell содержит три раздела в боковой панели.

### Overview

Главная страница показывает:
- количество обнаруженных файлов плагинов;
- количество успешно инициализированных модулей;
- версию хоста;
- общее состояние запущенного хоста.

Счётчик обнаруженных плагинов включает и модули, загрузка которых завершилась ошибкой. Смотрите состояние на странице Plugins.

### Plugins

Страница Plugins отображает нативные модули, найденные при последнем запуске:
- имя и версию плагина;
- описание, если автор его указал;
- состояние загрузки;
- сообщение об ошибке, если загрузка не удалась.

Состояния:
- **Discovered** — файл найден;
- **Loaded** — библиотека загружена и метаданные проверены;
- **Initialized** — плагин успешно прошёл инициализацию;
- **Failed** — загрузка, проверка или инициализация завершилась ошибкой.

В 0.1.x эта страница только показывает список. Кнопок установки, удаления, обновления или включения/выключения плагинов пока нет.

### Settings

Страница показывает путь к конфигурации и фактическую папку плагинов. Редактирование параметров из GUI пока не поддерживается.

## 4. Установка плагина вручную

В текущей версии используется простой файловый способ:

1. Закройте Stackwell.
2. Найдите папку `plugins` рядом с папкой `bin` в дистрибутиве (обычно `dist/plugins`).
3. Поместите туда один файл плагина: например, `example.dll`.
4. Запустите Stackwell снова.
5. Откройте Plugins и проверьте состояние модуля.

Каждый плагин — один файл библиотеки. Не создавайте отдельную папку для каждого плагина и не кладите туда исходники вместо DLL.

Плагин должен быть собран для той же платформы и архитектуры, что и Stackwell, и использовать совместимую версию Plugin API. Например, 64-битный процесс Windows загружает 64-битные DLL.

Удаление: закройте Stackwell и удалите соответствующий файл из папки `plugins`. Изменения списка видны после следующего запуска.

## 5. Командная строка

Откройте PowerShell или терминал в папке `bin` дистрибутива.

Показать доступные команды:

```powershell
.\stackwell.exe --help
```

Показать сведения о хосте:

```powershell
.\stackwell.exe info
```

Показать обнаруженные плагины:

```powershell
.\stackwell.exe plugins
```

Команда `plugins` показывает состояние, API version, путь к файлу и описание (если оно задано).

## 6. Конфигурация и файлы

Основной файл конфигурации:

`resources/config/config.json`

Начальные значения:

```json
{
  "application": {
    "name": "Stackwell",
    "version": "0.1.0"
  },
  "logging": {
    "level": "info",
    "file": "logs/stackwell.log",
    "max_size_mb": 5,
    "max_files": 3
  },
  "plugins": {
    "directory": "plugins"
  },
  "storage": {
    "directory": "data"
  }
}
```

Пути относительные и разрешаются от каталога дистрибутива (родительского каталога для `bin`), а не от текущей папки терминала.

- `plugins.directory` — где хост ищет DLL.
- `logging.level` — уровень журналирования.
- `logging.file` — путь к журналу.
- `logging.max_size_mb` и `logging.max_files` — параметры ротации журнала.
- `storage.directory` — каталог данных, зарезервированный для хранения.

Перед изменением конфигурации закройте Stackwell и сохраните резервную копию файла. Некорректный JSON или неверные значения могут помешать запуску.

## 7. Устранение проблем

**Приложение не запускается**
- Распакуйте архив полностью и проверьте, что `resources/config/config.json` находится рядом с `bin` в ожидаемой структуре.
- Проверьте журнал в `logs/stackwell.log`.
- Убедитесь, что используете сборку для своей архитектуры.

**Плагин не отображается**
- Убедитесь, что DLL лежит непосредственно в папке, указанной в `plugins.directory`.
- Перезапустите Stackwell: сканирование выполняется при запуске.
- Проверьте расширение файла и архитектуру DLL.

**У плагина состояние Failed**
- Прочитайте сообщение об ошибке в карточке плагина или журнале.
- Проверьте совместимость Plugin API и обязательные экспортируемые функции.
- Убедитесь, что зависимости DLL плагина доступны системе.

**Stackwell запускается без дополнительных функций**
Это нормально, если папка плагинов пуста. Функции не встроены в хост и появляются только вместе с установленными плагинами.

## 8. Безопасность

Плагины Stackwell — обычные нативные библиотеки. Они выполняются внутри процесса Stackwell с правами текущего пользователя. В версии 0.1.x нет песочницы, изоляции или системы разрешений для плагинов.

Устанавливайте DLL только из доверенных источников. Контрольная сумма помогает проверить целостность скачанного файла, но сама по себе не доказывает безопасность автора или кода.

## 9. Текущие ограничения

В версии 0.1.x нет встроенного каталога плагинов и автоматического установщика. Плагины устанавливаются вручную одним файлом DLL. Хост не предоставляет API для добавления собственных GUI-страниц плагинам, а Settings пока доступен только для просмотра.

См. [заметки о выпуске 0.1.0](releases/0.1.0.md).
